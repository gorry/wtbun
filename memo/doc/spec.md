## wtbun のウィンドウ
- 最初の起動では、wtbun の小さなウィンドウだけを出す
- 開いているプロジェクトをタブで並べる。タブには構成ファイルの `name`（なければフォルダ名）を出し、マウスを乗せるとフォルダの場所を出す
- タブの名前の左に、プロジェクトのアイコン（16×16）を出す（`ProjectIcon`）
  - プロジェクト直下の `.wtbun.ico`、`.wtbun.png` の順に探し、読めた最初のものを使う。どちらもない・読めないときは wtbun のアイコン（`app.ico`）
  - `.ico` などの複数の大きさを持つ画像は、いちばん大きいものを縮めて出す
  - 読むのは、開いたとき・開き直したとき・構成の編集ダイアログで保存したとき。開いている間にファイルを手で置き換えたときは、そのどれかで反映する
  - `name` は開くときに読む。開いている間に手で書き換えたときは、次に開いたときから（構成の編集ダイアログで変えたときは、保存した時点でタブの名前も変わる）。前回のウィンドウを引き取るときも構成ファイルから読む（読めなければフォルダ名。ファイルは作らない）
- 「＋」と「≡」のボタンの記号は、Windows のアイコン用フォント（Segoe Fluent Icons、なければ Segoe MDL2 Assets）の「追加」（U+E710）と「メニュー」（U+E700）を、タブのアイコンと同じ大きさ（16）で出す。字の枠いっぱいに描かれるフォントなので、普通の文字の「＋」「≡」より大きく、タブのアイコンとそろう
- 「＋」（プロジェクトを開く）でメニューを出し、開くフォルダーを選ぶ
  - 「フォルダーを選択…」：フォルダー選択のダイアログで選ぶ
  - 「履歴 >」：「＋」で開いたフォルダーの履歴から選ぶ。新しい順に最大 20 件。フルパスで表示する
    - 同じフォルダーをもう一度開くと先頭へ移す（大文字・小文字は区別しない）。履歴は `%APPDATA%\wtbun\history.json` に保存する（`ProjectHistory`）
    - 前回の起動で開いていたプロジェクトを開き直すときは、履歴を変えない
    - 選んだフォルダーがなければ「フォルダーが見つかりません。」とパスを出して開かない。履歴からは消さない
  - 「履歴の消去…」：消去するフォルダーを選ぶダイアログ（`ClearHistoryWindow`）を、タブ列の真下に出す
    - 「無効になったフォルダー（N 件）」：フォルダーがなくなったか、あっても `.wtbun.toml` がなくなったフォルダーだけを消す（`ProjectHistory.IsUsable`）。既定はこちら。調べるのはダイアログを開いたときの 1 回だけ
    - 「すべてのフォルダー（N 件）」：全部消す
    - 無効になったフォルダーがなければ、「無効になったフォルダー」は選べなくし、「すべてのフォルダー」を選んでおく
    - ボタンは「消去」「キャンセル」。誤って消さないよう、Enter は「キャンセル」
  - 履歴が空のときは、「履歴」と「履歴の消去…」は選べない
  - すでに開いているフォルダーをもう一度開いたときは、タブを増やさず、どうするかを選ぶダイアログ（`AlreadyOpenWindow`）をタブ列の真下に出す
    - 同じフォルダーかどうかは、フルパスの文字列で比べる（大文字・小文字と末尾の `\` は区別しない。`Project.IsSameDirectory`）
    - 「開き直す」：「プロジェクトを開き直す」と同じ（確認はこのダイアログで済んでいるので、もう一度は聞かない）。`.wtbun.toml` を読み直して開き直す。実行中のコマンドは終了する
    - 「前面に表示」：そのタブを選び、ウィンドウを前面に出すだけ。`.wtbun.toml` は読み直さない。既定（Enter）はこちら（実行中のコマンドを誤って終了させないように）
    - 「キャンセル」（Esc・閉じるボタンも）：何もしない。タブも選ばない
    - Windows Terminal の閉じる確認も出る設定のときは、「プロジェクトを開き直す」の確認と同じ案内を添える
    - ウィンドウがまだ開いている途中か、開き直している途中なら、ダイアログを出さずにタブを選ぶだけにする。前回の起動のプロジェクトを開き直すときも、ダイアログを出さない
    - 選んでいる間にそのウィンドウが閉じられたときは、何もしない
    - 履歴では、どれを選んでもそのフォルダーを先頭へ移す
- タブを選ぶ（選ばれているタブをもう一度クリックするのも含む）と、そのプロジェクトの Windows Terminal のウィンドウを最前面に出す。最小化されていれば元に戻す
- タブの並べ替えは、ドラッグするか、右クリックの「左へ移動」「右へ移動」で行う
- タブの右クリックの「プロジェクトの構成を編集…」で、`.wtbun.toml` をダイアログで編集する（「構成の編集ダイアログ」を参照）
- タブの右クリックの「プロジェクトを開き直す」で、確認してから、ウィンドウを閉じて今の `.wtbun.toml` で開き直す。実行中のコマンドは終了する
  - 確認で「いいえ」なら何もしない。既定は「いいえ」
  - タブの位置は変えない。開き直したタブを選ぶ。ウィンドウの位置とサイズはほかのウィンドウと同じ
  - `.wtbun.toml` が読めないときは、メッセージを出して閉じない
  - Windows Terminal の閉じる確認で取り消されたときは、そのまま残す
  - 開き直している途中はタブを外さない。新しいウィンドウが開けなければ、プロジェクトを開くときと同じメッセージを出してタブを外す
  - ウィンドウを開いている途中は何もしない
- タブの「×」または右クリックの「閉じる」で、確認してから、プロジェクトのウィンドウに閉じるよう求める。実行中のコマンドは終了する
  - 確認で「いいえ」なら何もしない。既定は「いいえ」
  - ウィンドウがもうなければ、確認せずにタブを外す
  - Windows Terminal の「複数のタブを閉じるときに警告する」がオンのときは、確認が重ならないよう、オフにする案内を確認の文に添える。開き直しの確認も同じ。オフなら添えない
    - 確認のたびに設定ファイルの `warning.confirmCloseAllTabs`（古い名前は `confirmCloseAllTabs`）を読む。`false` のときだけオフとみなす（キーがない・読めないときは、既定どおりオン）。複数の版が入っていれば、ストア版の設定を見る（`TerminalSettings.WarnsWhenClosingTabs`）
  - ウィンドウを前面に出してから閉じる。タブが複数あると Windows Terminal も確認を出し、取り消されれば閉じない
  - タブは、ウィンドウが実際に閉じたときに外す
  - ウィンドウを開いている途中と、開き直している途中は何もしない
  - Windows Terminal のタイトルバーの閉じるボタンと Alt＋F4 も、同じ確認を出す。確認は前面に出し、「いいえ」なら入力先を元のウィンドウに戻す
    - しくみ：`CloseRequestWatcher` が低レベルフック（WH_MOUSE_LL・WH_KEYBOARD_LL、専用スレッド）で入力を受ける。左クリックは、管理中のウィンドウに WM_NCHITTEST（0.1 秒で打ち切り）で尋ねて `HTCLOSE` のときだけ止める。ボタンの外で離したら何もしない。答えがなければクリックを通す。Alt＋F4 は、管理中のウィンドウが前面のときだけ止める。F4 の繰り返しと離す操作も止める
    - 対象は wtbun が開いたウィンドウだけ。ほかの Windows Terminal のウィンドウ、最小化・最大化ボタン、本文のクリック、F4 だけの入力はそのまま届く
    - 確認やダイアログを出している間に押しても、確認は増えない
  - タスクバーから閉じる操作とシステムメニューの「閉じる」も、同じ確認を出す。ウィンドウに直接届く `WM_CLOSE` と `SC_CLOSE` の `WM_SYSCOMMAND` を止める
    - しくみ：`TerminalCloseGuard` が `wtbunhook.dll` を `SetWindowsHookEx`（WH_CALLWNDPROC）で Windows Terminal に読み込ませ、登録メッセージ `wtbun.hook.attach` を受けた DLL がウィンドウをサブクラス化する。閉じる要求を止めたら `wtbun.hook.closeRequested` をタブ列のウィンドウへ送る。wtbun から閉じるときは `wtbun.hook.closeNow` で通してもらう（`TerminalWindows.RequestClose`）
    - wtbun がいない、または応答しないときは、要求をそのまま通す
    - wtbun の終了・サインアウト・シャットダウンの前に取り外す。強制終了したときは DLL が残るが、要求は通す。起動し直すと、残っていたウィンドウの知らせる先を付け替える
    - DLL は `%LOCALAPPDATA%\wtbun\hook\wtbunhook-<ハッシュ>.dll` にコピーして読み込む。残っていても、ビルドや更新の上書きを妨げないように
    - DLL がない・読み込めないときは、確認を出さずに閉じる（通常の動き）。今は x64 だけ
  - 次のときは、この確認を出さない：コマンドの終了（`exit` など）、タブが 1 つのときの Windows Terminal のタブの「×」、wtbun の終了
- 利用者が Windows Terminal 側でウィンドウを閉じたときも、0.5 秒ごとの確認で気づいてタブを外す
- 選ばれていたタブが外れたときは隣のタブを選ぶ。そのウィンドウは前面に出さない
- wtbun はタイトルバーのない細いタブ列で、選ばれているプロジェクトのウィンドウの真上に、見えている枠と同じ幅で付く
  - ウィンドウを動かしている間もついて行く
  - 利用者がタスクバーなどから直接ウィンドウを前面に出したときも、そのタブを選んでタブ列を付ける。ほかのアプリに隠れていたタブ列も前に出す（前面にはしない。「タブ列とターミナルを一緒に前に出す」を参照）
  - タブのない所をドラッグすると、タブ列と全プロジェクトのウィンドウを一緒に動かす
  - システムメニュー（Alt＋Space・タスクバーのボタンの Shift＋右クリック）の「移動」でキーボードから動かすときも同じ。Esc で取り消すと、全部が元の位置に戻る
  - プロジェクトがないときは、最後の位置にとどまる（最初は画面の中央）
- 右端の「≡」から「wtbun を終了」（「終了と復元」を参照）
- 「≡」の「環境設定…」で、表示する言語を選ぶダイアログ（`SettingsWindow`。題名は「環境設定 - wtbun」）を、タブ列の真下に出す（「表示する言語」を参照）
- 「≡」の「wtbun について…」で、アプリの情報のダイアログ（`AboutWindow`。題名は「wtbun について」）を、タブ列の真下に出す。ダイアログを出すメニューなので、末尾に「…」を付ける
  - アプリのアイコン、アプリ名（[Title] Text と ShortText）、バージョン（[Version] Text）、著作権表示（[Copyright] Text と Name）、リリースのページの URL（[URL] Release。新しいバージョンを探せるように。クリックすると既定のブラウザーで開く）
  - 「NOTICE」「LICENSE」のタブで、リポジトリ直下の `NOTICE`・`LICENSE` の本文を出す。ネットにつながっていなくても読めるよう、ビルドのときに exe に入れる（`EmbeddedResource`）。等幅で折り返さない。タブを切り替えてもウィンドウの高さは変えない
  - NOTICE のタブの下に「最新の内容を Web で表示」（[URL] Notice）
  - URL が Profile.ini にない（または http・https でない）ときは、そのリンクを出さない。ブラウザーを開けなければ「ブラウザーを開けません。」
  - 「バージョン情報をコピー」で、`Windows Terminal Bundler (wtbun) 2026.1106.1` の形の 1 行をクリップボードに入れる（問い合わせのときに貼り付けられるように）。ほかのアプリがクリップボードを使っていてコピーできなければ「コピーできませんでした。もう一度お試しください。」
    - しくみ：Win32 の API（OpenClipboard・SetClipboardData）で、文字列をその場でクリップボードに置く（`ClipboardText.TrySet`）。開けなければ 0.05 秒おきに 10 回まで試す。WPF の `Clipboard.SetText` は使わない（design.md の「クリップボードへのコピー」）
  - 「閉じる」（Enter・Esc でも閉じる）

## プロジェクトを開く
- プロジェクト直下の `.wtbun.toml` を読み、その構成で Windows Terminal のウィンドウを 1 つ開く
  - `wt.exe -w wtbun-<ランダムな16桁> new-tab ... ; new-tab ...` で、プロジェクトごとに名前付きのウィンドウを開く
  - 開く前と後の Windows Terminal のウィンドウ（クラス名 `CASCADIA_HOSTING_WINDOW_CLASS`）の一覧を比べ、新しく表示されたものをそのプロジェクトのウィンドウとして覚える。取り違えないよう、ウィンドウは 1 つずつ開く
  - 15 秒たっても見つからなければ、メッセージを出してタブを外す。wt.exe を起動できないときも同じ
- `.wtbun.toml` がなければ、既定の構成（説明のコメント付き）で作ってから開く
- `.wtbun.toml` が開けないときは、メッセージを出して開かない
  - 書き方が正しくない：何行目かを伝える（「.wtbun.toml の 3 行目が正しくありません。」）
  - 知らない項目がある：項目名を伝える（「.wtbun.toml の「titel」は使用できない項目です。」）
  - `name`・`version` を `[[tabs]]` の後ろに書いた（TOML ではそのタブの項目になる）：「.wtbun.toml の「name」は最初の [[tabs]] より前に書いてください。」
  - 読み書きできない：アクセス権を確認するよう伝える
- 開いている間に利用者が別の Windows Terminal のウィンドウを開くと、そちらを取り違えることがある

## 構成ファイル `.wtbun.toml`

TOML（1.1）で書く。コメント（`#` から行末まで）を書ける。値を `'…'` で囲むと、Windows のパスやコマンドの `\`・`"` をエスケープせずに書ける。

```toml
version = 1
name = 'My Project'

[[tabs]]
title = 'main'
dir = '.'

[[tabs]]
title = 'files'
dir = '.'
profile = 'Windows PowerShell'
command = 'powershell -NoExit -Command Get-ChildItem'

[[tabs.panes]]
split = 'right'
size = 0.4
command = 'npm run dev'
```

| 項目 | 内容 |
|---|---|
| `version` | 形式の版。今は `1` |
| `name` | wtbun のタブに出す名前。省略する（または空白だけ）と、フォルダ名を出す。最初の `[[tabs]]` より前に書く |
| `[[tabs]]` | 開くタブ 1 つぶん。書いた順に開く。1 つもなければ既定のタブ 1 つで補う（ファイルは書き換えない） |
| `title` | タブのタイトル。省略すると Windows Terminal の既定 |
| `dir` | 開始フォルダ。相対パスはプロジェクトのフォルダが基準 |
| `command` | タブで実行するコマンドライン。省略するとプロファイルの既定 |
| `profile` | Windows Terminal のプロファイル名または GUID。省略すると既定のプロファイル |
| `append_command_line` | `true` なら `command` をプロファイルのコマンドラインの後ろに付け足す（`--appendCommandLine`）。`command` がなければ付けない |
| `tab_color` | タブの色。`#RGB` か `#RRGGBB`（`--tabColor`）。ほかの書き方は止める（`InvalidConfigValueException`。「.wtbun.toml の「tab_color」が正しくありません。'#RRGGBB' か '#RGB' の形式で書いてください。」） |
| `color_scheme` | 配色の名前。プロファイルの配色の代わりに使う（`--colorScheme`）。名前は確かめない |
| `suppress_application_title` | `true` なら `--suppressApplicationTitle`、`false` なら `--useApplicationTitle`。省略するとプロファイルの設定 |
| `inherit_environment` | `true` なら `--inheritEnvironment`、`false` なら `--reloadEnvironment`。省略すると Windows Terminal の既定（コマンドラインがあれば引き継ぐ） |
| `selected` | `true` なら、開いたときにこのタブを選んでおく（全部のタブを開いた後に `focus-tab -t 番号`）。1 つのタブにだけ書ける。どのタブにもなければ、最後のタブ（Windows Terminal の既定） |
| `[[tabs.panes]]` | 直前の `[[tabs]]` のタブを分割して開くペイン 1 つぶん（wt.exe の split-pane）。書いた順に、直前のペイン（最初はタブ）を分割する。`title` から `inherit_environment` までの項目と、下の 3 つを書ける |
| `split` | 新しいペインを置く向き。`'right'`（右。`-V`）か `'down'`（下。`-H`）。省略すると Windows Terminal が縦横の長さで決める。ほかの値は止める（「.wtbun.toml の「split」が正しくありません。'right' か 'down' を書いてください。」） |
| `size` | 新しいペインの大きさ。分割する前のペインに対する割合（`--size`）。0 より大きく 1 より小さい数。省略すると半分。範囲の外は止める（「…「size」が正しくありません。0 より大きく 1 より小さい数を書いてください。」） |
| `selected`（ペイン） | `true` なら、タブの中でこのペインを選んでおく。1 つのタブで 1 つのペインにだけ書ける。どのペインにもなければ、最初のペイン（`[[tabs]]` で開いたもの）を選ぶ。2 つ以上あれば止める（「.wtbun.toml の「selected = true」が多すぎます。選ぶタブは 1 つ、タブの中で選ぶペインは 1 つにしてください。」。タブの 2 つ以上も同じ） |
| `duplicate` | `true` なら直前のペインを複製する（`-D`）。このときは `dir` を書いたときだけ `-d` を渡す（書かなければ複製元のフォルダー） |

- `title` から `profile` は文字列、`append_command_line`・`suppress_application_title`・`inherit_environment` は `true`／`false`。型が違えば、書き方が正しくないときと同じに何行目かを伝える
- `split`・`size`・`duplicate` はペインだけの項目。`[[tabs]]` に書くと「使用できない項目」として止める。`panes = …` のように `[[tabs.panes]]` 以外の形で書いたときも止める
- タブのタイトルは、選ばれているペインのタイトルになる（Windows Terminal の動き）。分割しただけでは最後に開いたペインが選ばれたままになるので、ペインのあるタブでは、ペインを全部開いた後に `move-focus first` で最初のペインへ移り、`selected` のペインがあれば `move-focus nextInOrder` をその番号（1 から）の回数だけ続ける。これで、既定ではタブの `title` がタブに出る。`tab_color` も、選ばれているペインの色
  - `nextInOrder` は説明書では「作った順」だが、画面で試すと、ペインの並び（左上から）の順で動いているように見えた。書いた順と並びが合う普通の分割（`right` の後に `down` など）では同じになる
  - 4 回試して 1 回、2 回目の分割（`down`）が、直前のペインではなく最初のペインの下にできた（Windows Terminal 1.24。原因は分からない。「マウスの位置でペインを選ぶ」設定はオフ）。そのときは選ぶペインもずれる
- `append_command_line` から下の項目は、wt.exe の new-tab のオプションのうち、アイコン以外の全部に当たる（タブのアイコンを指定するオプションは wt.exe にない。2026-11-06 に Windows Terminal 1.24 で確かめた）
- 上の表にない項目があれば、書き間違いとして止める（読み込みに使う Tomlyn は、知らない項目を黙って読み飛ばすため）
- 既定の構成は `[[tabs]]` に `dir = '.'` だけ。ファイルの先頭に、何のファイルか・書き換えたらいつ効くか、各項目の説明、値の囲み方をコメントで入れ、タブを増やすときの例もコメントで入れておく（README を読まなくても書き換えられるように）
  - タブを増やす例は、コメントを外せばどの Windows でもそのまま動くものにする。全項目を書いた例にし、Windows に最初からあるものだけを使い、終わってもタブが閉じないもの（`profile = 'Windows PowerShell'`・`command = 'powershell -NoExit -Command Get-ChildItem'`）
    - プロファイルは、Windows Terminal に最初からあり、名前が言語で変わらない「Windows PowerShell」にする（コマンド プロンプトは、日本語では「コマンド プロンプト」、英語では「Command Prompt」と名前が変わる）
    - 環境やプロジェクトによって動かないもの（`npm run dev`）は、説明の中で「たとえば」として挙げるだけにする
- 読み込みは Tomlyn（`TomlSerializer`、キーは snake_case）。ファイルは UTF-8 で書く
- `title`・`dir`・`profile` の中の `;` は、wt.exe の区切りと見なされないように `\;` にして渡す
- `command` は、書いた引用符を活かすためにそのまま渡す（`;` だけ `\;` にする）
  - Windows Terminal はコマンドラインをそのまま起動するので、拡張子のないプログラム名は `.exe` しか探さない。`npm`（実体は `npm.cmd`）のようなバッチファイルは「指定されたファイルが見つかりません」になる
  - そこで、先頭のプログラム名を、タブの開始フォルダ・システムのフォルダ・PATH から探し、`.exe` がなくて `.cmd`・`.bat` があれば（または `.cmd`・`.bat` と書いてあれば）、`cmd /c "…"` で包む（`CommandLauncher.Prepare`）。cmd は最初と最後の引用符を外すので、中の引用符はそのまま渡る
  - コマンドが終わるとタブも閉じる（Windows Terminal の既定）
  - `append_command_line = true` のときは、プロファイルのコマンドに渡す引数なので、`cmd /c` で包まない
- コマンドラインの前には、いつも `--` を置く（`-- npm run dev`）。ないと、付け足すときの `-Command` や `/k` を wt.exe が自分のオプションとして読もうとして、タブやペインがすぐ閉じる（2026-11-06 に Windows Terminal 1.24 で確かめた。`-NoExit` だけなら閉じなかった）
- タブの引数の後ろにペインの ` ; split-pane …` を並べ、ペインがあれば ` ; move-focus …` を続ける。全部のタブの後ろに、`selected` のタブがあれば ` ; focus-tab -t 番号`（0 から）
- `color_scheme` の `;` も `\;` にして渡す。引数の順は、ペインなら `-V`／`-H`・`--size`・`-D` の後に、`-d`・`--title`・`-p`・`--tabColor`・`--colorScheme`・タイトル・環境変数・`--appendCommandLine`・`--`・コマンドライン
- 例：`-w wtbun-xxxx new-tab -d "H:\proj\web" ; split-pane -V --size 0.4 -d "H:\proj\web" -- cmd /c "npm run dev" ; new-tab …`

## 構成の編集ダイアログ

`.wtbun.toml` を手で書かずに編集する。タブ列の真下に出す（タブ列の中央に合わせると、画面の上端で上にはみ出るため）。

- 編集する項目：プロジェクト名（`name`）、開くタブとペインの一覧、タブとペインごとの全項目
- 一覧には、タブのすぐ下にそのタブのペインを字下げして並べる（「└ タイトル」。タイトルがなければ「（ペイン）」）
  - 「タブを追加」：一覧の最後にタブを足す
  - 「ペインを追加」：選んでいるタブ（ペインならそのタブ）の、最後のペインの後ろに足す
  - 「複製」：選んでいる行と同じ内容の行を作って選ぶ。ペインはそのすぐ後ろに入れる。タブはそのペインも一緒に複製し、元のタブ（とペイン）の後ろに入れる（`Duplicate_Click`・`EditItem.Clone`）
    - 「開いたときに選択」は 1 つだけなので、複製した行（タブを複製したときはタブの行）には付けない。タブを複製したときのペインは、新しいタブの中で元と同じにする
  - 「削除」：ペインはそのペインだけ。タブはそのペインも一緒に削除する
  - 「上へ」「下へ」：ペインは同じタブの中でだけ動かす。タブはペインと一緒に、隣のタブと入れ替える
- タブとペインのどちらにも、いちばん上に「開いたときにこのタブを選択」（ペインなら「…このペインを選択」）を出す（`selected`）。タブは全部のタブで 1 つ、ペインは同じタブのペインで 1 つだけにする（チェックすると、ほかのチェックを外す）。下に、選ばないときにどれが選ばれるかを添える
- 右側の項目は、タイトル・開始フォルダー・プロファイル・コマンド・「コマンドをプロファイルのコマンドの後ろに追加」・タブの色・配色・プログラムによるタイトルの変更・環境変数の順（プロファイルを選んでからコマンドを書く流れに合わせた）
- ペインを選ぶと、上に「分割の向き」（自動・右に分割・下に分割）、「サイズ（%）」（1〜99。空欄なら半分。ファイルの値は百分率に直して出し、欄を変えなければ元の値のまま書く）、「直前のペインを複製」を出す。正しくないサイズのまま保存すると「「（ペイン）」のサイズが正しくありません。1 から 99 までの数を入力してください。」と出し、そのペインを選ぶ
- ペインを選ぶと項目が増えて高くなるので、ダイアログの高さは画面の作業領域までにし、はみ出す分はスクロールする
- アイコン：今のアイコン（タブと同じもの）のプレビュー（48×48）と「インポート…」ボタンを、プロジェクト名の右に出す
  - 「インポート…」で選んだ画像（png・jpg・bmp・gif・ico・tif）の中央から、いちばん大きい正方形を切り抜いてプレビューに出す。縮小はしない
  - 「保存」で、プロジェクト直下に `.wtbun.png`（24 ビット RGB ＋ 8 ビットのアルファ、96 dpi）として書く。あれば上書きする。構成ファイルより先に書く。「キャンセル」なら書かない
  - インポートした後、`.wtbun.ico` があれば、タブにはそちらが出ることを添える
  - 画像が読めなければ「画像を読み込めません。別のファイルを選択してください。」。書けなければ「.wtbun.png を保存できません。アクセス権を確認してください。」と出してダイアログに戻る
- 開始フォルダの「参照…」で選んだフォルダは、プロジェクトの中なら相対パスにする
- プロファイルは、Windows Terminal の設定ファイルにある名前（隠しているものを除く）を候補に出す。手でも入力できる。読めなければ候補なし
- タブごとに、ほかの項目も編集する
  - 「コマンドをプロファイルのコマンドの後ろに追加」（`append_command_line`）：チェックを外すと項目を書かない。ファイルに `false` と書いてあれば、チェックを変えない限り残す
  - 「タブの色」（`tab_color`）：入力欄の右に色の見本を出す。正しくない書き方のまま保存すると「「（タブ）」のタブの色が正しくありません。#RRGGBB か #RGB の形式で入力してください。」と出し、そのタブを選ぶ
  - 「配色」（`color_scheme`）：Windows Terminal に最初からある配色（1.24 の defaults.json にある 14 個。`TerminalSettings.BuiltInColorSchemes`）と、設定ファイルの `schemes` の名前を候補に出す。手でも入力できる
  - 「プログラムによるタイトルの変更」（`suppress_application_title`）：プロファイルの設定に従う（書かない）・許可する（`false`）・許可しない（`true`）
  - 「環境変数」（`inherit_environment`）：既定（書かない）・Windows Terminal から引き継ぐ（`true`）・新しく読み込む（`false`）
- 最後の 1 つのタブは削除できない（ペインは全部削除できる）
- 空欄の項目はファイルに書かない。前後の空白は取り除く
- 反映する時期：プロジェクト名は保存した時点。タブの内容は次にこのプロジェクトを開いたときから（開いているウィンドウには反映しない。「プロジェクトを開き直す」ですぐ反映できる）
- 開くとき
  - ファイルが読めない（書き方が正しくない・知らない項目がある）ときは、プロジェクトを開くときと同じメッセージを出して、ダイアログを開かない（壊れたファイルを上書きしないため）
  - ファイルがなければ、既定の構成を出す。開いただけではファイルを作らない
- 保存するとき（`ProjectConfigWriter`）
  - 何も変えていなければ、ファイルに書かない
  - タブの項目は `title`・`dir`・`profile`・`command`・`append_command_line`・`tab_color`・`color_scheme`・`suppress_application_title`・`inherit_environment`・`selected` の順に書く。ペインは、タブの後ろに 1 行空けて `[[tabs.panes]]` を書き、`split`・`size`・`duplicate` の後に同じ順で書く。`size` は `0.4` のように小数で書く
  - 変わった所だけを置き換える。`name` は値だけ。タブは、最初の `[[tabs]]` から最後のタブの終わりまでをまとめて書き直す。それより前と後ろのコメント（既定の説明と例も含む）、改行の種類は残す
  - `name` がなかったときは、`# name = …` のコメントの下、なければ最後の項目の下か、最初のタブの前に入れる
  - 値は `'…'` で書く。`'` や制御文字を含むときだけ `"…"` にしてエスケープする
  - コメントが消えるとき（タブの間のコメント、消した `name` の行末のコメント）は、保存するか確認する。「いいえ」ならダイアログに戻る
  - ダイアログを開いている間にファイルが書き換えられていたら、上書きせず、開き直すよう伝える
  - 書いた結果を読み直して、編集した内容にならないときは書き込まず、ファイルを直接書き換えるよう伝える（例：`tabs = [ … ]` の形で書いたファイルのタブを変えたとき）
  - 別のファイルに書いてから置き換える
- ダイアログを出している間はタブ列を操作できない。この間にターミナルを最小化すると、ターミナルは全部最小化されるが、タブ列とダイアログは残る。ターミナルを元に戻すと全部戻る

## ウィンドウの位置とサイズ
- 全プロジェクトのウィンドウを同じ場所・同じサイズにそろえる
  - 最初に開いたウィンドウの位置とサイズを使う。後から開いたウィンドウはそれに合わせる
- 選ばれているウィンドウを移動しているときは、ほかのウィンドウも同じ位置へ一緒に動かす。Esc で取り消すと一緒に戻る。前面には出さない
- 選ばれているウィンドウをリサイズすると、操作が終わった時点でほかのウィンドウにも反映する（リサイズ中に全部を描き直すと重いため）
- Win＋矢印キーなどでドラッグがないときは、動きが 0.2 秒止まった時点でほかのウィンドウにも反映する
- ウィンドウの上にはタブ列を置くので、見えている枠の上端は、作業領域の上端からタブ列の高さ（32 DIP。モニターの拡大率に合わせる）より下にする
  - 上に寄せられたら、その分だけ下にずらす。はみ出す分は高さを縮める
- 最大化されたら、本当の最大化はやめて、タブ列の下の作業領域いっぱいにする。この状態でもう一度最大化すると、その前の位置とサイズに戻す
- 最小化されたウィンドウは、そろえない
- タブを選んでウィンドウを前面に出すときも、位置とサイズを合わせてから出す

## まとめて最小化
- 選ばれているターミナルを最小化すると（最小化ボタン・タスクバーのボタンなど）、タブ列と全プロジェクトのウィンドウをまとめて最小化する。選ばれているタブは変えない
- wtbun のタスクバーのボタンで wtbun を最小化したときも同じ
  - wtbun が前面にいないときの 1 回目のクリックは、前面に出す動きになる（Windows の通常の動き）
- どれか 1 つを元に戻すと、全部を元に戻す
  - ターミナルを元に戻したときは、そのタブを選び、そのターミナルが前面になる
  - wtbun のタスクバーのボタンで元に戻したときは、選ばれているターミナルも前に出し、入力先は wtbun にする（「タブ列とターミナルを一緒に前に出す」と同じ）
- 選ばれていないウィンドウをタスクバーのボタンの右クリックなどで最小化したときは、そのウィンドウだけが最小化される
- 最小化している間の状態の保存では、タブ列の位置を保存しない（次の起動では、ウィンドウの真上に置き直す）
- しくみ：ほかのプロセスのウィンドウの最小化は、EVENT_SYSTEM_MINIMIZESTART・MINIMIZEEND で分かる。最小化は `WM_SYSCOMMAND` の `SC_MINIMIZE` をウィンドウに送る（`WindowOps.Minimize`）。前面になったウィンドウを順に最小化し（`MinimizeNext`）、前面にならなかったウィンドウは 0.12 秒ごとのタイマーで最小化する（`BeginMinimizeAll`・`MinimizeAll`。全部が最小化されるか 10 回で止める）

## 終了と復元
- 「≡」の「wtbun を終了」（または Alt＋F4、タスクバーから閉じる）で、状態を保存してから、プロジェクトのウィンドウを左のタブから 1 つずつ閉じ、全部終わったら wtbun も終わる（`ExitAsync`）
  - 1 つ閉じるよう求めたら（前面に出してから）、そのウィンドウが閉じるか、閉じる確認が取り消されるまで待ってから次へ進む。確認が出ている間は待ち続け、確認が出ないまま 1.5 秒たっても閉じなければ、取り消されたとみなす。確認が出ているかは、UI オートメーションで確認の「すべて閉じる」ボタン（AutomationId が `PrimaryButton`）があるかで見る（`TerminalWindows.IsConfirmingClose`）
  - まとめて閉じるよう求めないのは、Windows Terminal が全ウィンドウを 1 つのプロセスで動かしていて、閉じる確認を同時に 1 つしか出さず、確認が出ている間のほかのウィンドウへの求めを無視するため（まとめて求めると、1 つしか閉じなかった）
  - 閉じている間は、wtbun のタブ列は操作できない。状態を保存し直さず、閉じたウィンドウのタブも外さない（次の起動で開き直すため）
  - サインアウト・シャットダウンのときは待たずに終える
  - タブが複数あるウィンドウは Windows Terminal が確認を出す。取り消されたウィンドウは残り、次の起動でそのまま使う
  - 確認が要らなければ、Windows Terminal の設定の「操作」で「複数のタブを閉じるときに警告する」をオフにしてもらう
- 状態は `%APPDATA%\wtbun\state.json` に保存する。中身は、開いていたプロジェクト（並び順・フォルダ・ウィンドウ名・ウィンドウハンドル）、選んでいたタブ、全ウィンドウの位置とサイズ、タブ列の位置
  - 変更（開く・閉じる・並べ替え・選ぶ・位置とサイズ）があるたびに、0.5 秒まとめてから保存する。wtbun が強制終了しても、直前の状態が残る
  - Windows のサインアウト・シャットダウンのときも保存する
  - 別のファイルに書いてから置き換えるので、書いている途中で終わっても壊れない。読めなければ初めての起動と同じに扱う
- 起動すると、保存したプロジェクトを同じ順番で開き直し、選んでいたタブのウィンドウを前面に出す
  - 保存したウィンドウハンドルのウィンドウが残っていれば（閉じる確認で取り消された、wtbun だけが終わった）、新しく開かずにそのまま使う
  - 保存した位置がつながっていないモニターの上なら、その位置は使わない
  - フォルダが見つからないプロジェクトは開かず、まとめてメッセージを出す
  - Windows を再起動した後などに、たまたま同じウィンドウハンドルの別の Windows Terminal のウィンドウがあると、それを使ってしまうことがある

## 起動時の引数
- `--data-dir フォルダー`（または `--data-dir=フォルダー`）：状態（`state.json`）・設定（`settings.json`）・フォルダーの履歴（`history.json`）の保存先を変える。指定がなければ `%APPDATA%\wtbun\`。相対パスは起動したときのフォルダが基準
  - 試験で、利用者の状態（開いていたプロジェクト）を使わずに wtbun を動かすためのもの。環境変数 APPDATA を変えても保存先は変わらない（既知のフォルダの API で決まる）
  - `--data-dir` の後ろにフォルダがなければ、「保存先のフォルダーが指定されていません。--data-dir の後ろにフォルダーを指定してください。」と出して終わる（終了コード 1）
- `--lang 言語`（または `--lang=言語`）：表示する言語を、この起動の間だけ変える。`settings.json` の記録は変えない（「表示する言語」を参照）
  - 言語は `en-US`・`ja-JP`（大文字・小文字は区別しない。`en`・`ja` だけでもよい）
  - 選べない言語なら、「言語の指定が正しくありません。--lang の後ろに次のどれかを指定してください：en-US, ja-JP」と出して終わる（終了コード 1）
- 引数が正しくなくて終わるときは、初めての起動でも `settings.json` を作らない（メッセージの言語は Windows の表示言語から決める）
- 知らない引数は無視する

## 表示する言語
- 英語（`en-US`）と日本語（`ja-JP`）。画面の文言・メッセージ・最初に作る `.wtbun.toml` のコメントが変わる
- 初めて起動したとき（`settings.json` に言語がないとき）に、Windows の表示言語（`CultureInfo.CurrentUICulture`）から決めて `settings.json` の `language` に記録する。以後は記録した言語で動く
  - 表示言語が日本語なら `ja-JP`、そのほか（選べる言語にないもの）は `en-US`（`Loc.Detect`）
- 「≡」の「環境設定…」のダイアログ（`SettingsWindow`）で変えられる
  - 言語の一覧は、その言語自身の名前で出す（「English」「日本語」）
  - 「OK」で記録し、その場で切り替える（開き直さなくてよい）。今の言語と同じなら何もしない
  - `--lang` で上書きしているときは、今の（上書きした）言語を選んだ状態で開く。別の言語を選ぶと記録して切り替える
- `--lang` で、記録を変えずにこの起動の間だけ上書きできる
- 変わらないもの
  - メッセージボックスのボタン（「はい」「OK」など）と、フォルダー・ファイルを選ぶダイアログ：Windows の表示言語のまま
  - 日付や数の書き方（`CultureInfo.CurrentCulture`）：Windows の地域の設定のまま。サイズ（%）の入力もこれで読む
  - すでにある `.wtbun.toml` のコメント：作ったときの言語のまま（項目名と値は言語によらない）
  - Windows Terminal の閉じる確認をオフにする案内は、Windows Terminal の画面の項目名を書いているので、wtbun の言語と Windows Terminal の表示言語が違うと名前が合わない
- 仕組み
  - 文言は `src/Wtbun/Localization/Strings.resx`（英語。既定）と `Strings.ja.resx`（日本語）。キーは `画面_内容` の形（例：`Config_Save`）。`{0}` などは実行時に入る値。英語の resx の comment は翻訳する人への説明
  - 日本語はサテライト アセンブリ `ja\Wtbun.resources.dll` に入る（配布物にも入れる）。英語は exe の中（`NeutralLanguage` が `en-US`）
  - XAML は `{l:Tr キー}`（`TrExtension`）、コードは `Loc.Get`・`Loc.Format` で使う。`Loc.Apply` で言語を変えると、XAML の文言は Binding で変わる。略名を入れるメニュー（「wtbun について…」「wtbun を終了」）は `MainWindow.ApplyMenuTexts` で作り直す
  - キーが見つからないときは `[キー]` と出す

## 設定
- 「≡」のメニューで切り替える。`%APPDATA%\wtbun\settings.json` に保存する
- 「環境設定…」：表示する言語（「表示する言語」を参照）
- 「ターミナルをタスクバーに表示」：管理下の Windows Terminal のウィンドウをタスクバーに出すか。初期値は出す
  - オフにすると、管理下のウィンドウのボタンをタスクバーから外す（ITaskbarList）。後から開いたウィンドウ・引き取ったウィンドウも外す。Alt＋Tab には出る
  - エクスプローラーが再起動したときは、外し直す
  - wtbun を終了するときは、閉じる確認で取り消されて残ったウィンドウを選べるよう、ボタンを戻してから閉じる
  - wtbun が強制終了すると、ボタンを外したウィンドウはそのまま残る（次の起動で引き取れば、また wtbun から選べる）

## タブ列とターミナルを一緒に前に出す
- どちらが前面に来ても、前後関係を上からタブ列、選ばれているターミナルの順にする（入力先は変えない）
- タスクバーのボタンなどで wtbun が前面に来たら、選ばれているターミナルを持ち上げてから、タブ列を持ち上げる。ターミナルをタスクバーに出さないときでも、wtbun のボタンでターミナルを見えるようにするため
- 選ばれているターミナルが前面に来たら、タブ列を持ち上げる
- 持ち上げるときは、いったん最前面指定（HWND_TOPMOST）にしてからすぐ外す（HWND_NOTOPMOST）（`WindowOps.LiftWithoutActivating`）。HWND_TOP は前面にいないプロセスからは効かず、Windows Terminal のウィンドウは「wtbun のすぐ後ろ」に置く指示を出すと wtbun の上に来てしまうため
- タブ列をターミナルの上にするのは、「ウィンドウの下に影を表示する」が有効なときに、ターミナルの影でタブ列が暗くならないようにするため。ほかのウィンドウからターミナルをクリックしたときは、持ち上げるまでの 0.2 秒ほど暗く見えることがある
- どちらも、前面になったという知らせの時点では、前面になった方がまだいちばん上に上がりきっていないことがあるので、すぐに 1 回、0.15 秒後にもう 1 回置き直す（`KeepTogether`。0.15 秒の間に別のウィンドウが前面になっていたら、2 回目はしない）
- プロジェクトを開いたウィンドウは、wtbun がそのウィンドウだと分かる前に前面になっていて、前面になった知らせを見逃すので、分かった時点で前面なら同じように置く

## アイコン
- アプリのアイコンの元は、リポジトリ直下の `wtbun.icon.png`（256×256）
- そこから作った `src/Wtbun/app.ico`（16・20・24・32・40・48・64・256 ピクセル）を、`Wtbun.csproj` の `ApplicationIcon` で exe に入れる。WPF のウィンドウは `Icon` を指定しなければ exe のアイコンを使うので、タブ列・ダイアログ・タスクバーも同じアイコンになる
- `app.ico` はリソースとしても入れ、プロジェクトのアイコンがないときにタブに出す（`ProjectIcon.Default`）
- `app.ico` はビルドでは作らない。`wtbun.icon.png` を変えたら、手で作り直す（例：Python の Pillow で `Image.open('wtbun.icon.png').save('src/Wtbun/app.ico', sizes=[(16,16),(20,20),(24,24),(32,32),(40,40),(48,48),(64,64),(256,256)])`）

## リリース用パッケージ（release.cmd）
- リポジトリ直下の `release.cmd` で作る。できるもの（どちらも `release/` の下。git には入れない）
  - `release/（ShortText）_（Version）/`：リリース版の実行ファイル一式（日本語の文言の `ja\Wtbun.resources.dll` を含む）と、README.md・README.en.md・LICENSE・NOTICE
  - `release/（ShortText）_（Version）.zip`：そのフォルダーごと固めたもの（展開するとフォルダーが 1 つできる）
- 名前の（ShortText）は `Profile.ini` の [Title] ShortText、（Version）は [Version] Text。ビルドと同じ読み方にするため、`dotnet msbuild -getProperty` で `Directory.Build.props` のプロパティ（`ProfileShortTitle`・`Version`）を読む
- 実行ファイルは `dotnet publish -c Release -p:DebugType=none` で作る（.pdb は入れない）。.NET 10 のランタイムを使う形（self-contained ではない）
- `wtbunhook.dll` は `Wtbun.csproj` の `PublishHook` で発行先にコピーする。ビルドでは C++ ツールがなくても続けるが、パッケージでは必須とし、なければ止める
- 同じ名前のフォルダー・zip があれば、消してから作り直す
- zip は Windows の `tar.exe`（`%SystemRoot%\System32\tar.exe`）で作る。PATH に Git の tar（GNU tar）があると、`H:\…` のようなパスを接続先のホスト名と取り違えて失敗するため
- 失敗したら終了コード 1

## アプリ名・バージョン（Profile.ini）
リポジトリ直下の `Profile.ini` に、アプリ名などの定数がある。著作者だけが書き換え、プログラムからは読むだけ。

- ビルドのとき、`Directory.Build.props` が `Profile.ini` を読んでプロパティにし、`Directory.Build.targets` がコードから使う定数クラス `AppProfile` を `obj` の下に作る（`Profile.g.cs`。手で直さない。git にも入らない）
- 必要な値（[Title] Text・ShortText、[Version] Text・Number、[Copyright] Text）がなければ、ビルドを止める

| 値 | 使う所 |
|---|---|
| [Title] Text | 実行ファイルの製品名・説明、「wtbun について」のアプリ名（`AppProfile.Title`） |
| [Title] ShortText | wtbun のウィンドウ名とタスクバーの名前、メッセージの題名、「≡」の「（略名） を終了」、構成ファイル名 `.（略名）.toml`、保存先 `%APPDATA%\（略名）\`、Windows Terminal のウィンドウ名の接頭辞（`AppProfile.ShortTitle`） |
| [Version] Text | 実行ファイルのバージョン（製品バージョンにコミットのハッシュは付けない。`IncludeSourceRevisionInInformationalVersion`）、「wtbun について」のバージョン（`AppProfile.Version`） |
| [Version] Number | `AppProfile.VersionNumber`（今は使っていない） |
| [Copyright] Text | 実行ファイルの著作権表示、「wtbun について」の著作権表示（`AppProfile.Copyright`） |
| [Copyright] Name | 実行ファイルの会社名、「wtbun について」の著作権表示の 2 行目（`AppProfile.Author`。なくてもよい） |
| [URL] Project | `AppProfile.ProjectUrl`（今は使っていない。なくてもよい） |
| [URL] Release | 「wtbun について」のリリースのページの URL（`AppProfile.ReleaseUrl`。なくてもよい） |
| [URL] Notice | 「wtbun について」の「最新の内容を Web で表示」（`AppProfile.NoticeUrl`。なくてもよい） |
| [AppId] | 今は使っていない |

- このドキュメントで「wtbun」「`.wtbun.toml`」「`%APPDATA%\wtbun\`」と書いているのは、[Title] ShortText が `wtbun` のときの名前。README.md・README.en.md も同じ
- README.md・README.en.md の題名・著作権表記・連絡先と、NOTICE の先頭（アプリ名・略名・著作権表示・URL）には、[Title] Text・ShortText・[Copyright] Text・[URL] Project の値を書いている（どれもビルドしないファイルで読み込めないため。値が変わったらすべて直す）
