## ssh のプロファイルにコマンドを付け足すと、プロンプトのないシェルが開く（質問）
- ユーザーの報告：プロファイル「momiji」（コマンドラインは `C:\Windows\System32\OpenSSH\ssh.exe momiji`）、コマンド `zsh -c "cd ~/mcf/ae/ANADOS_gorry && exec zsh -l"`、「コマンドをプロファイルのコマンドの後ろに追加」をオンで開くと、$PROMPT が空のシェルが開く。目的は、ssh で momiji にログインして ~/mcf/ae/ANADOS_gorry でシェルを開くこと
- 調べたこと：
  - wtbun が wt.exe に渡す引数は書いたとおり（`-p momiji --appendCommandLine -- zsh -c "cd … && exec zsh -l"`）。wtbun の問題ではない
  - 原因（ssh の動き）は 2 つ：
    - ssh はコマンドを付けると端末（TTY）を割り当てない。そのため zsh が対話用に動かず、プロンプトが出ない
    - ssh は、ホスト名より後ろの引数を空白でつないでリモートのシェルに渡す。引用符は Windows 側で外れるので、リモートでは `zsh -c cd ~/mcf/ae/ANADOS_gorry && exec zsh -l` になる。`cd` は `zsh -c` の中だけで終わり、`exec zsh -l` はホームで動く

## 改行コードをそろえる（.gitattributes）

- ユーザーの質問：LF と CRLF がどう混ざっているか
  - 答え：LF だけのファイルが 53、CRLF だけが 4（`.wtbun.toml`・`NOTICE`・`AssemblyInfo.cs`・`wtbun.slnx`）、1 つのファイルの中で混ざっているものが 2（`.gitignore` は dotnet のテンプレートの部分が CRLF で後から足した部分が LF、`memo/log/20261030.md` は 1〜18 行目が CRLF で残りが LF）
- ユーザーの判断：LF に自動でそろえる。`wtbun.slnx` だけ LF でよいか調べる
  - 調べたこと：LF にした `wtbun.slnx` のコピーで、`dotnet sln list` と `dotnet build` は問題なし。`dotnet sln add` は、何も追加しなくてもファイル全体を CRLF で書き直した。読むときはどちらでもよく、ツールが保存すると CRLF になる
  - 決めたこと：リポジトリの中は LF。作業フォルダーでは `*.slnx` を CRLF にする（ツールが保存しても改行が変わらないように）。`*.cmd`・`*.bat` も CRLF にする（cmd.exe は LF だとラベルへのジャンプが誤動作することがある）
- `.gitattributes` を作った（`* text=auto eol=lf`、`*.slnx`・`*.cmd`・`*.bat` は `eol=crlf`、`*.png`・`*.ico` は binary）
- `git add --renormalize .` で登録し直し、改行が変わる作業フォルダーのファイル（`.gitignore`・`NOTICE`・`memo/log/20261030.md`・`AssemblyInfo.cs`・`build.cmd`）を取り出し直した
