# 2026-10-30

## ターミナルを前面にしたとき、タブ列も前に出す
- ユーザーの指示：wtbun とターミナルのウィンドウが前面にないとき、ターミナルを前面にしたら、wtbun も一緒に前面に出るようにする
- 今の作り：ターミナルが前面になったとき（`OnTerminalForeground`）に、タブ列を `WindowOps.BringToTopWithoutActivating`（SetWindowPos の HWND_TOP、SWP_NOACTIVATE）でいちばん上に置いていた
- 調べたこと：APPDATA を一時フォルダーにして Debug の wtbun を動かす使い捨ての試験（試験用のプロジェクト 1 つ、メモ帳をタブ列に重ねる）で、
  - ターミナルが前後関係のいちばん上に来ても、タブ列はメモ帳の下のままだった（`terminal > notepad > wtbun`）
  - 前面にいないプロセスから HWND_TOP でいちばん上に置く指示は、無視された（順番が変わらない）
  - 前面にいないプロセスからでも、ターミナルのすぐ後ろに置く指示（hWndInsertAfter にターミナル）は効いた（`terminal > wtbun > notepad`）。いったん HWND_TOPMOST にしてから HWND_NOTOPMOST に戻すのも効いた（`wtbun > terminal > notepad`）が、一瞬最前面のウィンドウになるので使わない
- 直したこと：`OnTerminalForeground` で、タブ列を `WindowOps.PlaceBehind(_ownHandle, hWnd)`（前面になったターミナルのすぐ後ろ）に置くようにした
- 確かめたこと：Debug でビルド（wtbun は動いていなかった）。上の API の効き方は試験で確かめた
- 確かめられなかったこと：実際にマウスでターミナルを前面にしたときの動き。試験用のプログラムからのクリックが、毎回、試験用のターミナルと同じ位置にある別の Windows Terminal のウィンドウ（「コマンド プロンプト」）に当たって、前面が変わらなかった
- 気づいたこと：この試験では wtbun を起動すると、Windows Terminal のウィンドウが 3 つ増えていた（タブ「コマンド プロンプト」、「コマンド プロンプト」「✳ wtbun」など）。ユーザーに聞くと、ユーザーの実際のプロジェクト（wtbun・gtexp はコマンド プロンプトと Claude Code、ghrlog はコマンド プロンプト）が正しく開いていたものだった
- 試験のやり方の誤り：保存先を一時フォルダーにするつもりで、wtbun を環境変数 APPDATA を変えて起動していたが、wtbun の `Environment.GetFolderPath(SpecialFolder.ApplicationData)` は環境変数 APPDATA を見ない（既知のフォルダーの API で決まる）。そのため試験の wtbun は、ユーザーの本物の `%APPDATA%\wtbun\state.json` を読んで、ユーザーの 3 つのプロジェクトを開き、試験の終わりに閉じていた（wtbun を起動した試験は 7 回）。Claude Code のタブ（`command = 'claude'`）もそのたびに起動して閉じられた。Windows Terminal の閉じる確認はオフの設定なので、確認なしで閉じていた。試験のクリックは、それらのウィンドウに当たっていた（キー入力はしていない）。試験の時間帯にできた Claude Code のセッションの履歴ファイルはなかった
  - 本物の state.json は、3 つのプロジェクトと並びは元のままだが、位置とサイズ（370,922〜1796,1929）と選んでいるタブ（ghrlog）は試験のときの状態で上書きされた。元の値は分からない
  - 2026-10-28 の「終了したとき 1 つしか閉じない」の試験も「APPDATA を一時フォルダーにして」と書いてあり、同じことになっていた可能性がある
  - 試験用のターミナルとして覚えたウィンドウもユーザーのプロジェクトのものだった。タブ列を前に出す API の効き方（HWND_TOP は無視され、すぐ後ろに置く指示は効く）は、どのウィンドウでも同じなので、結論は変わらない
- 一時フォルダーは消した

## 保存先を指定する起動時の引数
- ユーザーの指示：試験で利用者の状態を使わずに動かせるよう、保存先を指定できる仕組みを足す
- 作ったもの：
  - 起動時の引数 `--data-dir フォルダー`（または `--data-dir=フォルダー`）。状態（state.json）と設定（settings.json）の保存先を変える。指定がなければ `%APPDATA%\wtbun\`。知らない引数は無視する。フォルダがなければ「保存先のフォルダーが指定されていません。--data-dir の後ろにフォルダーを指定してください。」と出して終わる（終了コード 1）
  - `App.xaml` の StartupUri をやめ、`App.OnStartup` で引数を読んで（`ApplyOptions`）から MainWindow を作るようにした（MainWindow を作ると設定と状態を読み始めるため）
  - `UserDataFile.Folder` を変えられるようにした（`UseFolder`）
  - spec に「起動時の引数」、README の「手元で動かす（開発）」に使い方を書いた
- 試験の途中で見つけて直したこと：プロジェクトが 1 つもないときに wtbun を閉じても終わらなかった。`ExitAsync` は、閉じるウィンドウがないと待たずに最後まで進むので、`Close()` がまだ `OnClosing` の中で呼ばれ、WPF に無視されていた（2026-10-28 の「終了したとき 1 つしか閉じない」で入った作り）。最後の `Close()` を `Dispatcher.BeginInvoke(Close)` にして、`OnClosing` を抜けてから閉じ直すようにした
- 確かめたこと：Debug でビルド（ビルドの前に wtbun が動いていないことを確かめた）。コンソールを持たない使い捨ての試験用プログラムで、
  - 空の一時フォルダーを `--data-dir` で指定すると、Windows Terminal のウィンドウが 1 つも開かず、閉じると終わり（終了コード 0）、一時フォルダーに state.json（プロジェクトなし）ができること（直す前は終わらなかったので、残った試験の wtbun を、引数で試験のものと確かめてから終わらせた）
  - 試験用のプロジェクト 1 つだけの状態を書いた一時フォルダーを `--data-dir=` で指定すると、ウィンドウが 1 つだけ（タブ isolated）開き、閉じると終わってウィンドウも閉じ、一時フォルダーの state.json にそのプロジェクトが残ること
  - `--data-dir` だけを指定すると、メッセージを出して終わること（終了コード 1）
  - ユーザーの `%APPDATA%\wtbun\state.json` が、試験の前後で中身（MD5）も更新日時も変わっていないこと
  - 一時フォルダーは消した

## タブ列とターミナルが一緒に前に出ない（続き）
- ユーザーの報告（画面の写真 2 枚）：まだ、wtbun のタブ列だけが前に出てターミナルがほかのウィンドウの後ろにある状態や、ターミナルだけが前に出てタブ列がほかのウィンドウの後ろにある状態になる。ユーザーの wtbun は動いておらず、Debug（4:13 のビルド）には前の修正が入っていた
- 調べたこと：`--data-dir` で一時フォルダーを指定し、試験用のプロジェクト 1 つで wtbun を動かす、コンソールを持たない使い捨ての試験で、
  - 開いた直後、ターミナルが前面なのに、タブ列の上にユーザーの Claude アプリのウィンドウが重なっていた（写真の 2 枚目と同じ）。開いたウィンドウは、wtbun がそのウィンドウだと分かる前（`TerminalLauncher` が見つける前）に前面になっていて、`OnTerminalForeground` で自分のウィンドウと分からず何もしていなかった
  - クリックでの確認は、クリックする所がユーザーのほかのアプリ（TortoiseGit・Claude アプリ）に覆われていて、できなかった。1 回目の試験で、タブ列の空いている所のつもりのクリックが Claude アプリのウィンドウに当たった（クリック 1 回。キー入力はしていない）。その後は、クリックする所が試験用のウィンドウでなければクリックしないようにした
  - AttachThreadInput と SetForegroundWindow で前面を切り替える方法は、効かなかった（前面がターミナルのまま変わらない）
- 考えたこと（確かめていない）：前面になったという知らせ（EVENT_SYSTEM_FOREGROUND）の時点では、前面になったウィンドウがまだ前後関係のいちばん上に上がりきっていないことがある。そのときに「すぐ後ろに置く」と、上がる前の位置に置かれてしまう。写真の 1 枚目（wtbun が前面に来たときにターミナルを持ち上げる `RaiseSelectedTerminal`）も 2 枚目も、これで説明できる
- 直したこと：
  - `KeepTogether`：前面になった方（タブ列かターミナル）のすぐ後ろにもう一方を置く（`PlaceTogether`）。すぐに 1 回、0.15 秒後（`RaiseRetryDelay`・`_raiseTimer`）にもう 1 回置く。0.15 秒の間に別のウィンドウが前面になっていたら 2 回目はしない（`WindowOps.IsForeground`）。`OnTerminalForeground` と `RaiseSelectedTerminal`（wtbun が前面に来たとき）で使う
  - `OnTerminalOpened`：開いたウィンドウが、分かった時点で前面なら `KeepTogether`
  - spec の「wtbun が前面に来たとき」を「タブ列とターミナルを一緒に前に出す」に書き直した
- 確かめたこと：Debug でビルド（ビルドの前に wtbun が動いていないことを確かめた）。上の試験（クリックも前面の切り替えもしない）で、開いた直後に、見えているウィンドウの中でターミナルのすぐ後ろがタブ列になり、タブ列の中央にタブ列が見えること（2 回とも。直す前は Claude アプリのウィンドウが見えていた）。ユーザーの state.json は使っていない。一時フォルダーは消した
- 試していないこと：ほかのウィンドウの後ろにあるターミナルをクリックしたとき、wtbun のタスクバーのボタンやタブ列をクリックしたとき（写真の 2 つの状態）。ユーザーに試してもらう

## wtbun を前面にしたとき、ターミナルが前に出ない
- ユーザーの報告：ターミナルを前面にしたときに wtbun も前に出るのはできた。wtbun を前面にしたときに、ターミナルも前に出るのはまだできていない
- 調べたこと：`--data-dir` で一時フォルダーを指定した wtbun（試験用のプロジェクト 1 つ）とメモ帳で、クリックも前面の切り替えもせずに、前後関係だけを変える使い捨ての試験（ビルドの前に wtbun が動いていないことを確かめた）
  - ターミナルを「タブ列のすぐ後ろ」に置く指示（SetWindowPos の hWndInsertAfter にタブ列。今の作り）を出すと、毎回ターミナルがタブ列の上に来た（`terminal > wtbun > notepad`。3 回）。SWP_ASYNCWINDOWPOS を付けても同じ（1 回だけ思った順になったが、そのときは始めの並びがそろっていなかった）。同じ指示で wtbun のタブ列（WPF のウィンドウ）は思った位置に来るので、Windows Terminal のウィンドウだけが違う動きをする
  - ターミナルを「メモ帳のすぐ後ろ」に置く指示も効かなかった（ターミナルがメモ帳の下に行かない）
  - ターミナルをいったん HWND_TOPMOST にしてからすぐ HWND_NOTOPMOST に戻すと、`wtbun > notepad > terminal` から `terminal > wtbun > notepad` になった（3 回とも。最前面の指定は残らない）
- 直したこと：`WindowOps.LiftWithoutActivating`（HWND_TOPMOST → HWND_NOTOPMOST、SWP_NOACTIVATE）を足し、wtbun が前面になったとき（`PlaceTogether` で前面になった方が wtbun のとき）は、ターミナルをこれで持ち上げるようにした。ターミナルがタブ列の上になるが、重ならないので一緒に前に出て見える。spec・design に書いた
- 確かめたこと：Debug でビルド。上の試験で、持ち上げる方法の効き方。一時フォルダーは消した
- 試していないこと：実際に wtbun を前面にしたとき（タスクバーのボタン・タブ列のクリック・Alt＋Tab）の動き。ユーザーに試してもらう
