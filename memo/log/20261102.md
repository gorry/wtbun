## タブ列と全ターミナルをまとめて最小化
- ユーザーの指示：ターミナルの最小化ボタンで、アクティブなウィンドウだけが最小化される。wtbun と管理下のターミナル全部を最小化する手段もない。最小化ボタンで全部を最小化できるのが一番よい。可能か、不可能なら代替手段を考えて試す
- 調べたこと：`--data-dir` の一時フォルダーの wtbun（試験用のプロジェクト 3 つ）で、最小化ボタンの位置をクリックした（クリックする所が試験のウィンドウのときだけ）。`EVENT_SYSTEM_MINIMIZESTART` は別プロセスからも受け取れた。順番は `MINIMIZESTART term3` → `FOREGROUND term2` で、今の作りでは次のターミナルのタブが選ばれていた（保存された選択が 2 から 1 に変わった）
- 結論：最小化ボタンでの全部の最小化はできる。ボタンを横取りせず、最小化が始まった知らせを受けて残りを最小化する
- 作ったもの：
  - `WindowEventWatcher`：`MinimizeStarted`・`MinimizeEnded`
  - `MainWindow`：`OnTerminalMinimizeStarted`・`OnTerminalMinimizeEnded`・`OnStripStateChanged`・`BeginMinimizeAll`・`MinimizeNext`・`MinimizeAll`・`IsAllMinimized`・`RestoreAll`・`SelectWithoutActivating`
  - `WindowOps.Minimize`（`WM_SYSCOMMAND` の `SC_MINIMIZE` を送る）
  - `MainWindow.xaml`：`ResizeMode` を `CanMinimize` にした（wtbun のタスクバーのボタンで最小化できるように）
  - `SaveState`：最小化している間はタブ列の位置を保存しない。`FollowStrip`：タブ列が最小化されていれば動かさない
  - spec に「まとめて最小化」、design に「最小化はまとめて行う」を書いた
- 作ってみて分かったこと：
  - `ShowWindow`（`SW_SHOWMINNOACTIVE`・`SW_MINIMIZE`）で別プロセスのウィンドウを最小化すると、最小化された `term2` が前面に残ることがあった。入力が見えないウィンドウに入ってしまう。0.12 秒待っても、前面になった順に最小化しても直らなかった。残った状態から外す方法（`SW_MINIMIZE`・`SC_MINIMIZE`・隠してから最小化）も効かなかった
  - 最初から `SC_MINIMIZE` をウィンドウに送る形にすると、残らなくなった。効いた理由は確かめていない（ウィンドウ自身のスレッドで処理されるので、前面を次へ渡せるのだと考えている）
  - タブ列が先に最小化された経路でも、次のターミナルが前面になる知らせを「元に戻した」と取り違えて全部が戻ったので、全部が最小化されるまでは途中の扱いにした（`_minimizeTimer.IsEnabled`）
- 確かめたこと：Debug でビルド（ビルドの前に wtbun が動いていないことを毎回確かめた）。キー入力なし。ユーザーの `state.json` は変わっていない。一時フォルダーは消した
  - 最小化ボタンのクリック：3 回起動して各 3 回、計 9 回とも、全ウィンドウとタブ列が最小化され、前面はほかのアプリになった。元に戻すと（`SwitchToThisWindow`。Alt＋Tab の代わり）、全部が戻り、そのターミナルが前面で、順番は `strip > term3 > term2 > term1`
  - 別のターミナル（term1）を戻すと、そのタブが選ばれ（保存された選択 0）、`strip > term1 > ...`。タブ列の位置とサイズは変わらない
  - wtbun のタスクバーのボタンを UI オートメーションで押して戻すと、全部が戻り、前面はタブ列
  - 同じ押し方で最小化になったときは、`MINIMIZESTART strip` → `term3` → `term2` → `term1` の順で全部が最小化され、前面はほかのアプリ。ただし UI オートメーションで押すと前面が動くので、最小化にならず前面に出すだけのこともあった
  - タブ列に `SC_MINIMIZE` を送ると全部が最小化され、そのまま閉じると全ウィンドウが閉じて終わる（終了コード 0。保存はプロジェクト 3 つ、選択そのまま、タブ列の位置 null）
  - 「ターミナルをタスクバーに表示」がオフでも、最小化ボタンで全部が最小化され、wtbun のボタンで全部が戻る。タスクバーの該当のボタンの数は変わらなかった
- 試していないこと：タスクバーのボタンを実際にマウスでクリックすること（試験のクリックは位置の確認で止まり、クリックしていない）、ターミナルのタスクバーのボタン、実際の Alt＋Tab、Win＋↓、Win＋M、Win＋D、選ばれていないウィンドウだけの最小化、目で見たときのちらつき、ボタン設定の変更後のタブ列の見た目
- ユーザーが確かめたこと：まとめて最小化について「動作確認OK」（上の「試していないこと」のどこまでを試したかは聞いていない）

## wtbun 自体の設定ファイルの形式
- ユーザーの疑問：プロジェクトの構成ファイルは TOML だが、wtbun 自体の設定はまだ JSON か
