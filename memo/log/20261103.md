## タスクバーから閉じる操作でも確認を出す（DLL の注入）
- 経緯：2026-11-02 の「Alt+F4 とタスクバーから閉じる操作でも確認を出す」の続き。ユーザーの判断で `SetWindowsHookEx` で進めた。試作を分けず、この PC で本体に組み込んで試した
- 作ったもの：
  - `src/WtbunHook/wtbunhook.cpp`：`HookProc`（WH_CALLWNDPROC）、`SubclassProc`。`WM_CLOSE` と `SC_CLOSE` を止めて、タブ列に `wtbun.hook.closeRequested` を送る
  - `src/WtbunHook/build.cmd`、`Wtbun.csproj` の `BuildHook`・`CopyHook`：`dotnet build` で DLL も作って出力フォルダーへコピーする。C++ ツールがなければ警告で続ける
  - `Native/TerminalCloseGuard.cs`：DLL をコピーして読み込み、ウィンドウごとに登録する。`TerminalWindows.RequestClose` は `TryCloseNow` を先に試す
  - `MainWindow`：`WndProc` で知らせを受ける。終了処理とサインアウトの前に取り外す。`ConfirmClosing` は、元のウィンドウがターミナルのときだけ入力先を戻す（タスクバーへ戻さない）。spec・design・README を更新した
- 作ってみて分かったこと：
  - ソースが UTF-8 だと cl がコードページ 932 で読み、コメントの直後の `#include <windows.h>` が読まれなかった。`/utf-8` で直した。`build.cmd` も日本語のコメントで cmd が誤動作したので英語にした
  - `exit` とタブの「×」は `WM_CLOSE` を通らず、確認は出ない。Windows Terminal の中で閉じているとみられる
- 確かめたこと（Debug ビルド、`--data-dir` の試験用 wtbun）。試験の前後で Windows Terminal のプロセスは同じ（落ちていない）：
  - 外から送った `WM_CLOSE` と `SC_CLOSE`（タスクバーと同じ種類の要求）で確認が前面に出る。「いいえ」で残り、「はい」で閉じてタブが消える。選ばれていないウィンドウでも、そのプロジェクトの名前で確認が出る
  - `exit` とタブの「×」は確認なしで閉じ、タブが消える
  - wtbun の終了で確認なしに全部閉じ、DLL も Windows Terminal から外れる
  - wtbun を強制終了すると、閉じる要求はそのまま通る。全部閉じると DLL も外れる
  - 強制終了の後に起動し直すと、残っていたウィンドウで新しい wtbun の確認が出る
  - 閉じるボタン、Alt+F4、タブの「×」と「閉じる」、開き直しの試験も通る（タブの「×」の試験は、確認中に閉じる手順を `WM_CLOSE` からタブの「×」に変えた）

  - 「複数のタブを閉じるときに警告する」がオンの PC での確認の流れ
  - セキュリティソフトでの検出（この PC では止められなかった）。ほかの PC
